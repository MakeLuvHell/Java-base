# 首页公告弹窗功能设计文档

## 概述

在 RuoYi-Vue 3.9.2 首页（index.vue）新增公告弹窗功能：用户登录后自动弹出未读公告，关闭后标记已读并逐条展示下一条。

## 变更范围

| 层 | 文件 | 操作 |
|----|------|------|
| 数据库 | `sql/ry_20260417_pg.sql`（参考） | 提供 PostgreSQL DDL（`notice_content` 为 TEXT） |
| 后端 Controller | `ruoyi-admin/.../controller/system/SysNoticeController.java` | 添加 `@Tag`、`@Operation` Swagger 注解 |
| 后端配置 | `ruoyi-admin/src/main/resources/application.yml` | 扩大 springdoc 扫描范围，新增 `system` 分组 |
| 前端页面 | `ruoyi-ui/src/views/index.vue` | 新增弹窗组件 + 加载/关闭/标记已读逻辑 |

**不变的层**：Service、Mapper、MyBatis XML、Frontend API 模块（现有 `listNoticeTop`、`markNoticeRead` 已满足）。

## 详细设计

### 1. 数据库

```sql
-- 公告表
CREATE TABLE sys_notice (
  notice_id         INTEGER   NOT NULL GENERATED BY DEFAULT AS IDENTITY,
  notice_title      VARCHAR(50) NOT NULL,
  notice_type       CHAR(1)     NOT NULL,        -- 1=通知 2=公告
  notice_content    TEXT        DEFAULT NULL,
  status            CHAR(1)     DEFAULT '0',     -- 0=正常 1=关闭
  create_by         VARCHAR(64) DEFAULT '',
  create_time       TIMESTAMP,
  update_by         VARCHAR(64) DEFAULT '',
  update_time       TIMESTAMP,
  remark            VARCHAR(255) DEFAULT NULL,
  PRIMARY KEY (notice_id)
);

-- 用户公告已读关联表
CREATE TABLE sys_notice_read (
  read_id    BIGINT       NOT NULL GENERATED BY DEFAULT AS IDENTITY,
  notice_id  INTEGER      NOT NULL,
  user_id    BIGINT       NOT NULL,
  read_time  TIMESTAMP    NOT NULL,
  PRIMARY KEY (read_id),
  CONSTRAINT uk_user_notice UNIQUE (user_id, notice_id)
);
```

注意：`notice_content` 使用 `TEXT` 而非 `BYTEA`，以支持 HTML 内容展示。

### 3. 前端变更

#### 3.1 弹窗组件（在 index.vue 中内嵌）

```vue
<el-dialog
  title="系统公告"
  :visible.sync="noticeDialogVisible"
  width="600px"
  top="8vh"
  @close="handleNoticeClose"
  append-to-body>
  <div v-if="currentNotice">
    <h3 style="margin-bottom: 12px;">{{ currentNotice.noticeTitle }}</h3>
    <div class="notice-content" v-html="currentNotice.noticeContent" />
  </div>
</el-dialog>
```

#### 3.2 业务逻辑

```js
import { listNoticeTop, markNoticeRead } from "@/api/system/notice";

data() {
  return {
    noticeDialogVisible: false,
    noticeList: [],
    currentNotice: null,
    noticeIndex: 0
  };
},
mounted() {
  this.fetchUnreadNotices();
},
methods: {
  fetchUnreadNotices() {
    listNoticeTop().then(res => {
      const unreadList = (res.data || []).filter(n => !n.isRead);
      if (unreadList.length > 0) {
        this.noticeList = unreadList;
        this.noticeIndex = 0;
        this.showNotice(0);
      }
    });
  },
  showNotice(index) {
    if (index < this.noticeList.length) {
      this.currentNotice = this.noticeList[index];
      this.noticeDialogVisible = true;
    }
  },
  handleNoticeClose() {
    const notice = this.currentNotice;
    if (notice && notice.noticeId) {
      markNoticeRead(notice.noticeId).then(() => {
        this.noticeIndex++;
        setTimeout(() => this.showNotice(this.noticeIndex), 300);
      });
    }
  }
}
```

### 4. 数据流

```
用户登录 → 进入首页
    → mounted → GET /system/notice/listTop
    → 有未读？ → 弹出 el-dialog 展示当前公告
        → 用户点击关闭 → POST /system/notice/markRead?noticeId=X
            → 成功 → 有下一条未读？ → 弹出下一条
                    → 没有下一条 → 关闭弹窗
```

### 5. 测试与调试要点

1. **后端调试**：通过 Swagger UI（`/swagger-ui.html`）选择「系统模块」分组，直接调用 `listTop` 和 `markRead` 接口
2. **前端验证**：登录后进入首页，观察弹窗是否自动弹出；关闭后检查是否不再重复弹出
3. **数据库准备**：在 `sys_notice` 表插入测试数据，登录用户在 `sys_notice_read` 表中无对应的已读记录
