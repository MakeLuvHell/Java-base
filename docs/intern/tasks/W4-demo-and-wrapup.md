# 任务书 W4：收口实践任务（按任务，不分天）

> **前置：** 建议已完成 W1～W3（至少 W1+W2；若缺 W3 导出，Demo 里对应项改为「说明未做原因」）。  
> **组织方式：** **按任务**推进，不强制按天。可并行准备，但 **T1→T4 建议按序验收**。  
> **原则：** 以「能讲清、能演示、能合入、能留文档」为主；新功能只做 **小而完整** 的可选实践，禁止大重构。

| 项 | 内容 |
| --- | --- |
| 阶段 | 第 4 周 |
| 难度 | ★★（表达 + 小实践） |
| 建议总工期 | 3～5 个工作日（自己排顺序） |
| 分支 | 已有 feature 继续，或 `feature/<你的名字>-wrapup` |
| 基线 | `master`（或导师指定已含 W2/W3 的分支） |

## T2. 权限对照实验（P0）

### 目标

用**两个账号**（或同一浏览器有权 + Swagger 换 Token）证明：前端隐藏 ≠ 后端安全。

### 你要做的

1. 准备：  
   - **A：** 管理员（或有 notice edit/export 的角色）  
   - **B：** 无 `system:notice:edit` 和/或无 `system:notice:export` 的用户（W2/W3 用过的即可）  
2. 用 A：完成一次「修改置顶」或「导出」（看你实现了什么）。  
3. 用 B：  
   - 看 UI：编辑/导出按钮是否不可见或不可用；  
   - **直调**对应接口（Swagger / 浏览器复制 curl）：期望 **403**。  
4. 填写实验记录：

```markdown
# W4 权限对照实验

## 账号
- A：角色/权限概要：
- B：缺哪些权限字符：

## 现象表
| 操作 | A（有权） | B（UI） | B（直调接口） |
| --- | --- | --- | --- |
| 修改公告/置顶 |  |  | 状态码： |
| 导出公告 |  |  | 状态码： |

## 结论（自己的话，≥3 句）
1. 菜单权限解决……
2. v-hasPermi 只……
3. @PreAuthorize 负责……
```

### 交付物

- 权限对照实验 Markdown（可附打码截图）

### 验收

- [ ] B 直调至少一条写操作或导出得到 **403**（或导师认可的未授权响应）  
- [ ] 结论句明确否定「只藏按钮就安全」  
- [ ] **一票否决：** 为了测通而注释权限注解

## T3. Demo 演示（P0）

### 目标

15 分钟内讲清「环境 + 登录 + 自己做过的功能 + 权限」。

### 脚本（可微调，勿删权限段）

| 分钟 | 块 | 必须覆盖 |
| --- | --- | --- |
| 0–2 | 架构 | 前后端分离；MySQL；Redis 会话 |
| 2–4 | 登录 | 验证码 → Token → `Authorization: Bearer` |
| 4–7 | 跟读结论 | 用户列表：页面 → API → Controller → 权限字符 |
| 7–12 | 业务 | 公告：置顶 / 筛选 / 导出 / 操作日志（有则演示，无则说明） |
| 12–15 | 权限 | 对照 T2：UI + 403；强调后端门禁 |

### Demo 前检查（结合 T1）

- [ ] T1 回归无阻塞项（或已声明规避）  
- [ ] A/B 账号能登录  
- [ ] 不展示真实密码；演示库可重建  

### 交付物

- 现场演示 **或** 录屏链接/文件  
- （可选）1 页讲稿提纲

### 验收

- [ ] 结构完整（架构 + 登录 + 业务 + 权限）  
- [ ] 现场至少成功 1 个业务操作 + 说清 1 次 403  
- [ ] 超时可接受（建议 ≤20 分钟）

### P1-C 安全只读实验（不改主分支代码）

1. **退出登录**或用无痕窗口。  
2. 访问（端口以本地为准）：  
   - Swagger UI（如 `http://localhost:8080/swagger-ui/index.html`）  
   - Druid（如 `http://localhost:8080/druid/`，若可打开）  
3. 记录：是否无需登录即可打开/看到什么。  
4. 写 **生产环境建议**（关闭、鉴权、仅内网等）——对照审计思路即可，**本任务不要求你改 SecurityConfig**。

```markdown
# W4 安全只读笔记
## 现象
## 风险（谁能利用）
## 生产建议（至少 3 条）
## 我是否改了代码：否
```

**验收：** 现象真实；建议合理；无提交危险配置到公网。

### P1-D DataScope 观摩（不改代码）

1. 在代码中搜索 `@DataScope`。

**验收：** 能口头区分「能不能调接口」vs「能看哪些行」；无强制改业务代码。
