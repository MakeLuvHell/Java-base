## 0. 本周交付结果

从一台只有 Docker/Compose 和 Git 的干净测试机出发，可以按文档完成：

```text
检出指定 commit
  → 注入测试环境配置
  → 构建前后端镜像
  → 启动 MySQL/Redis/后端/Nginx
  → 执行数据库迁移
  → 健康检查与冒烟测试
  → 查看日志和指标
  → 升级到新版本
  → 回滚应用与数据库
  → 恢复一份测试备份
```

### 本周明确不做

| 不做 | 原因 |
| --- | --- |
| Kubernetes、服务网格、Spring Cloud | 当前单体系统先把基本交付做好 |
| 直接部署公网或真实生产 | 安全与授权范围不允许 |
| 把数据库、JWT、Druid 密码写进镜像 | 必须运行时注入 |
| 只写 Dockerfile 不做升级/回滚 | “能启动一次”不等于可运维 |
| 以关闭安全校验换取健康检查通过 | 生产配置必须更严格 |

## 1. 默认部署拓扑

```text
Browser
   |
 Nginx :80
   |-- /         -> ruoyi-ui static files
   `-- /prod-api -> ruoyi-admin :8080
                         |-- MySQL :3306
                         `-- Redis :6379
```

Compose 至少包含：

- `mysql`：独立数据卷、健康检查、测试账号。
- `redis`：独立数据卷、密码通过环境变量注入。
- `backend`：仅依赖健康的 MySQL/Redis，非 root 用户运行。
- `web`：Nginx 托管前端并反向代理 API。
- 迁移步骤必须存在并形成启动门禁；可以使用一次性 `migration` 服务，也可以使用导师确认的等价 runner，但不能靠开发者临时手工挑 SQL。迁移成功后才启动 backend。

数据库和 Redis 端口默认不暴露到宿主机公网接口；仅在本地调试 profile 下按需映射。

## 2. 镜像与制品

### 2.1 后端镜像

- 使用多阶段构建或 CI 已产出的 jar，禁止在运行镜像保留 Maven 缓存和源码。
- 运行阶段使用明确版本的 JRE 17 基础镜像。
- 使用非 root 用户、只读应用目录和独立上传目录。
- JVM 内存、时区、日志目录通过环境变量配置并有合理默认值。
- 镜像标签至少包含版本或 commit SHA，禁止发布只有 `latest` 的唯一制品。

### 2.2 前端镜像

- 在固定 Node/npm 环境使用 `npm ci && npm run build:prod`。
- 运行镜像只包含 Nginx 和构建产物。
- Nginx 配置静态缓存、API 代理、上传大小和常用安全响应头。
- 前端 API 基础路径与 Nginx 代理保持一致，不写死测试机 IP。

### 2.3 `.dockerignore`

排除 `.git`、IDE 配置、`node_modules`、本地日志、测试报告、上传文件和密钥文件。不能因追求构建方便把整个开发目录复制进镜像。

## 3. 配置与安全基线

### 3.1 配置分层

至少区分 `dev/test/prod`：

| 配置 | 生产默认 |
| --- | --- |
| 数据库/Redis/JWT secret | 环境变量或密钥文件注入，无仓库默认生产值 |
| `springdoc.swagger-ui.enabled` | false |
| Druid 控制台 | 关闭或仅管理网络可达 |
| CORS | 显式前端 Origin 白名单 |
| `logging.level.com.ruoyi` | info 或 warn |
| 文件目录 | 挂载持久化卷，目录权限最小化 |
| generator | 生产构建禁用、移除依赖或入口不可达 |
| 注册接口 | 按部署需求明确关闭或限制 |

若生产 profile 仍使用仓库示例 secret/口令，应用应拒绝启动或由部署门禁阻断。

### 3.2 暴露面验证

在测试环境以未登录身份验证：

- Swagger/OpenAPI UI 不可用。
- `/druid/**` 不可公网访问。
- `/profile/**` 不能用于读取工单受保护附件。
- Actuator 只公开必要健康信息，不暴露环境变量、beans 或完整配置。
- MySQL/Redis 不从非管理网络直接连接。

### 3.3 镜像和依赖扫描

CI 对最终镜像执行基础漏洞扫描并归档报告。阻断规则与 W11 一致；例外必须有风险说明、负责人和到期日。

## 4. 数据库迁移、备份与回滚

### 4.1 启动顺序

```text
MySQL healthy
  → 备份/确认恢复点
  → 执行待应用的 V 脚本
  → 记录迁移版本和校验值
  → backend healthy
  → web healthy
  → 冒烟测试
```

迁移失败时不得继续启动新版本 backend。

### 4.2 备份与恢复

使用测试数据完成：

1. 记录当前应用和迁移版本。
2. 导出数据库备份并计算校验值。
3. 删除或修改一组测试工单。
4. 恢复到独立数据库实例。
5. 验证工单数量、状态、流转、通知和附件元数据。

备份文件不能进入 Git，也不能包含真实用户数据。

### 4.3 回滚策略

分别写清：

- **仅应用回滚：** 数据库向后兼容时，将镜像切回上一 SHA。
- **应用 + 数据库回滚：** 新版本写入不兼容结构时，停止写流量，执行对应 U 脚本或恢复备份，再启动旧镜像。
- **附件处理：** 数据库回滚不自动删除附件卷；需要独立核对/清理步骤。

回滚命令必须使用明确镜像标签和明确测试数据库，禁止用未展开变量指向不确定目标。

## 5. 健康检查与可观测性

### 5.1 健康检查

| 层 | 检查 |
| --- | --- |
| Nginx | 静态页可访问，API 代理正确 |
| Backend | 进程存活 + 应用 ready；依赖未就绪时不能报告 ready |
| MySQL | 可接受查询 |
| Redis | `PING` 成功 |

区分 liveness 与 readiness：数据库短时不可用不应让 Nginx 假装全站健康。

### 5.2 日志

- Nginx 与后端日志带时间、状态码、耗时和 request/trace ID。
- 前端请求生成或透传 request ID，后端响应回传，便于一次请求串联排查。
- 登录、Token、密码、完整附件路径和敏感请求体不进入普通日志。
- 容器日志有轮转/大小限制，不能无限占满磁盘。

### 5.3 指标与告警草案

至少采集/展示：

- HTTP 请求数、错误率、P95 延迟。
- JVM 内存、线程和 GC 基础指标。
- 数据库连接池使用量。
- 工单创建/解决数、通知失败数、附件清理失败数。

本周可以只在测试环境接入轻量指标端点和看板；不要求部署完整大型监控平台。指标端点必须鉴权或仅管理网络可达。

## 6. 性能基线

使用脱敏生成数据准备至少 10,000 条工单、50,000 条流转/评论和跨部门用户，记录：

- 工单列表常用筛选的 SQL 与 `EXPLAIN`。
- 详情 + 时间线查询次数，检查明显 N+1。
- 列表和详情的 P50/P95 响应时间。
- 未读通知查询使用的索引。
- 大量在线会话时 Redis `KEYS` 风险及替代/限制建议。

只针对有证据的慢点增加索引或调整查询；不能为了“优化”盲目缓存所有列表。优化前后使用同一数据集和命令对比。

## 7. 发布与回滚操作手册

新增一份可复制执行的 runbook，至少包含：

```markdown
# 测试环境发布手册

## 前置检查
- commit / 镜像 SHA
- CI 状态
- 配置与 secret 来源
- 数据库版本与备份

## 发布
- 构建/拉取镜像
- 执行迁移
- 启动顺序
- 健康检查
- 冒烟测试

## 观察
- 日志
- 错误率/延迟
- 工单关键指标

## 回滚判定
- 哪些现象立即回滚

## 回滚步骤
- 应用
- 数据库
- 附件

## 发布后记录
- 时间、操作者、版本、结果、遗留项
```

命令里的环境名、Compose project 名和数据库名必须明确，不允许复制后可能误操作其他环境。

## 9. 推荐执行顺序

### 第 1 天：拓扑与威胁面

- 完成部署图、配置矩阵、镜像设计和回滚方案。
- 准备隔离测试环境与脱敏数据。

### 第 2 天：镜像与 Compose

- 完成后端/前端镜像、Nginx 和 Compose。
- 从空卷启动依赖、迁移和应用。

### 第 3 天：配置、安全与观测

- 落地测试用 prod profile。
- 验证暴露面、健康检查、request ID、日志和指标。

### 第 4 天：性能与故障演练

- 执行 10k 数据基线和针对性优化。
- 模拟 MySQL/Redis/附件目录不可用，观察健康与日志。

### 第 5 天：升级、回滚和恢复

- 从上一版本升级到当前版本。
- 执行应用回滚、数据库回滚和备份恢复。
- 按 runbook 由另一位同学或导师复现一次。

## 10. 必测矩阵

| 场景 | 预期 |
| --- | --- |
| 空机器/空卷首次启动 | 迁移完成，应用健康，能登录和创建工单 |
| 缺少生产 JWT secret | 启动失败或部署门禁阻断 |
| 未登录访问 Swagger/Druid | 不可用或受控 |
| 非信任 Origin 预检 | 被 CORS 拒绝 |
| MySQL 未就绪 | backend 不报告 ready，迁移不跳过失败 |
| Redis 短时不可用 | 日志可定位，恢复后行为符合设计 |
| 发布新镜像 | 迁移、健康、冒烟均有记录 |
| 新版本健康检查失败 | 自动或手动停止继续发布并回滚 |
| 回滚到旧镜像 | 旧版本可运行且数据兼容 |
| 恢复测试备份 | 工单、流转、通知和附件元数据核对通过 |
| 日志抽样 | 无密码、Token、secret、敏感文件路径 |
| 10k 工单查询 | 有基线、EXPLAIN 和前后对比，不出现无界查询 |

## 11. 验收标准

- [ ] 干净测试机可按文档启动完整系统。
- [ ] 镜像可追溯到 commit SHA，运行容器使用非 root 用户。
- [ ] MySQL/Redis 不默认暴露到不可信网络。
- [ ] 生产配置无仓库默认 secret/口令，Swagger/Druid/generator 已收敛。
- [ ] 数据库迁移失败会阻止新版本启动。
- [ ] 健康检查区分进程存活与服务就绪。
- [ ] 一次请求可通过 request ID 串联 Nginx 和后端日志。
- [ ] 备份恢复、应用回滚和数据库回滚均在测试环境实做。
- [ ] 性能优化有相同数据集的前后证据。
- [ ] runbook 由非作者成功复现，命令不会误指向其他环境。
- [ ] CI、镜像扫描、部署、冒烟和回滚记录齐全。

## 13. 常见坑与求助

| 坑 | 修正方向 |
| --- | --- |
| 容器启动了但应用不可用 | 区分 container running、liveness、readiness |
| 镜像每次构建结果不同 | 固定基础镜像、工具版本、lockfile 和构建参数 |
| prod 仍读取仓库默认密码 | 配置外置并做启动/部署校验 |
| 回滚旧镜像后 SQL 报错 | 发布前评估向后兼容或准备数据库回滚 |
| 日志看不到一次请求全链路 | Nginx 生成/透传 request ID，后端回传并记录 |
| 加索引后没有证据 | 保存相同数据集下 EXPLAIN 和延迟对比 |

求助时附：环境名、commit/镜像 SHA、Compose 状态、健康检查、首个失败服务日志、迁移版本、配置来源（不含 secret 值）、回滚点和已执行命令。
