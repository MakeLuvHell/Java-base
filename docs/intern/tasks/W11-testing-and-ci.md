## 0. 本周交付结果

最终应做到：

```text
干净检出
  → 固定版本的 JDK/Maven/Node/npm
  → 可重复安装依赖
  → 后端单测/集成测试
  → 前端测试
  → 前端生产构建
  → 文档/迁移检查
  → CI 统一给出通过或失败
```

当前仓库没有自动化测试、业务 CI workflow 和前端 lockfile。本周必须提交真实断言和真实门禁，不接受空测试套件、`TODO assert` 或 `|| true` 把失败伪装成成功。

### 本周明确不做

| 不做 | 原因 |
| --- | --- |
| 为追求覆盖率给 getter/setter 写大量无意义测试 | 测试应保护业务风险 |
| 一开始要求全仓 90% 覆盖率 | 先让新增 ticket 模块形成可持续基线 |
| CI 自动部署生产 | W12 再做部署与回滚 |
| 在 workflow 中写数据库密码或 Token | 使用测试容器和 CI Secrets |
| 依赖扫描失败后永久 `continue-on-error` | 允许短期分级，但必须有退出计划 |

## 1. 工具链与依赖可复现

### 1.1 固定版本

| 工具 | 默认要求 |
| --- | --- |
| JDK | 17 |
| Maven | 团队固定版本；优先增加 Maven Wrapper |
| Node | 22 LTS，若兼容性验证失败需记录并由导师确定版本 |
| npm | 跟随固定 Node 版本 |

新增 `.nvmrc`、`.node-version` 或团队已有的等价文件，不能只在 README 写“装一个 Node”。

### 1.2 前端 lockfile

1. 确认使用 npm 后，停止忽略 `package-lock.json`。
2. 在固定 Node/npm 版本下重新生成并提交 lockfile。
3. 本地和 CI 使用 `npm ci`，不再用会漂移依赖的 `npm install` 作为门禁命令。
4. lockfile 大量变化必须解释原因，禁止顺手升级全部依赖。

### 1.3 后端测试依赖

按模块最小引入：

- JUnit 5 / `spring-boot-starter-test`。
- Mockito（由 starter 提供时不重复声明）。
- Spring Security Test。
- Testcontainers MySQL；Redis 可使用 Testcontainers 或导师认可的测试容器方案。
- JaCoCo 只统计新业务包，初始门槛由导师确定，建议行覆盖率不低于 60%。

依赖版本优先跟随 Spring Boot BOM；禁止每个子模块各写一套不同版本。仓库没有继承 Spring Boot parent，必须显式确认 Maven Surefire 能发现 JUnit 5；必要时在根 POM 的插件管理中固定兼容版本。CI 日志中的 discovered/executed test 数必须大于 0，不能把“BUILD SUCCESS 但未发现测试”算通过。

## 2. 测试分层

### 2.1 纯单元测试（快）

不启动 Spring、不连接数据库，覆盖：

| 对象 | 关键用例 |
| --- | --- |
| 状态规则 | 合法/非法动作、参与者、终态、availableActions |
| 通知接收人 | 排除操作者、去重、不同事件接收人 |
| 文件策略 | 大小、扩展名、终态禁止上传、文件名清理 |
| 工单编号生成 | 格式、并发冲突重试策略，不使用 `select max` |

每条测试用例只验证一个明确行为，命名体现“条件_动作_结果”。

### 2.2 Service 集成测试（真实 MySQL/Redis）

使用可丢弃测试环境执行真实 Mapper 和事务：

- 创建、修改、逻辑删除与 DataScope 查询。
- 状态更新 + flow 插入同事务提交。
- flow 插入失败时工单状态回滚。
- 相同 requestId 幂等。
- 两个 version 并发更新只有一个成功。
- 通知唯一约束与已读条件包含 receiverId。
- 附件元数据失败后的补偿入口。

测试不能依赖开发者本机已有的 `ry-vue` 数据库，也不能清空共享库。

### 2.3 Controller/权限测试

至少覆盖：

| 场景 | 预期 |
| --- | --- |
| 未登录访问 ticket API | 401 |
| 已登录无权限访问写接口 | 403 |
| 有方法权限但不是参与者 | 业务拒绝且零写入 |
| A 读取 B 的通知 | 拒绝 |
| 非参与者下载附件 | 拒绝且无文件内容 |
| 合法请求参数错误 | 稳定校验错误，不进入 Service 写入 |

只 mock `PermissionService` 返回 true 不能证明完整权限链路；至少保留一组使用真实 Security 配置的集成用例。

### 2.4 前端测试

Vue 2 使用与当前版本兼容的 Vue Test Utils/Jest 组合，先覆盖高风险交互：

- `availableActions` 控制动作按钮。
- 动作提交时按钮禁用，成功刷新，失败保留输入。
- 并发冲突显示重新加载入口。
- 通知未读数为 0 时不显示徽标。
- 附件越权/失败不生成公开 URL。
- 查询重置恢复分页和筛选初始值。

不要对 Element UI 生成的大段 DOM 做脆弱快照；优先断言用户能看到和触发的行为。

## 3. 测试数据与数据库生命周期

### 3.1 Fixture

固定构造：

- 2 个部门和父子关系。
- 管理员、工单管理员、两个处理人、两个创建人、无权限用户。
- 覆盖全部状态的工单。
- 合法/非法流转、重复 requestId、并发 version。
- 已读/未读通知和合法/越权附件元数据。

Fixture 不能包含真实姓名、手机号、邮箱、文件或生产数据。

### 3.2 迁移验证

CI 必须验证两条路径：

```text
空库 → V001 → V002 → V003 → 测试

W8 基线库 → V002 → V003 → 测试
```

至少验证一次 `U003 → U002 → U001` 的回滚顺序；回滚测试使用独立临时库。

### 3.3 测试隔离

- 每个测试类/用例明确回滚或清理策略。
- 时间、当前用户、随机数通过可替换组件控制，避免偶发失败。
- 文件测试使用系统临时目录，结束后检查无残留。
- 并发测试使用超时，失败时输出双方结果，不能无限等待。

## 4. CI 设计

新增 `.github/workflows/ci.yml`（或团队平台的等价文件），建议拆为以下 job：

### 4.1 `docs-check`

- 检查 Markdown 本地链接。
- 检查 `git diff --check`。
- 检查迁移版本不重复、正向脚本有对应回滚说明。

### 4.2 `backend-test`

- JDK 17 + Maven 缓存。
- 启动隔离 MySQL/Redis 测试依赖。
- 执行 `mvn -B test` 或团队确定的 `verify`。
- 上传 Surefire/JaCoCo 报告，即使测试失败也保留报告。

### 4.3 `frontend-test-build`

- 固定 Node/npm。
- `npm ci`。
- 前端测试。
- `npm run build:prod`。
- 上传构建日志；是否上传 dist 由 W12 决定。

### 4.4 `dependency-audit`

- 后端依赖扫描和前端 audit 分开出报告。
- 明确阻断级别：新增 critical/high 默认阻断；已有问题需登记例外、负责人和到期日。
- 不能只显示绿色图标却丢弃扫描结果。

### 4.5 分支门禁

CI 在 push/PR 触发；完成稳定运行后，将必要 job 设为合并前必过。文档更新不应无条件跳过所有业务测试，路径过滤策略需由导师评审。

## 5. 强制设计评审（第 1 天）

编码前提交：

1. 测试金字塔及每层用例清单。
2. MySQL/Redis 测试环境选择和清理策略。
3. Fixture 用户、部门、状态和权限矩阵。
4. Node/npm/lockfile 决策。
5. CI job 依赖图、缓存和报告保存位置。
6. 扫描阻断规则与临时例外格式。
7. 预计最慢测试和总体时间预算。

导师必须确认测试确实覆盖业务规则，不是只验证 Spring 能启动。

## 6. 推荐执行顺序

### 第 1 天：基线与设计

- 记录当前构建、测试文件数、lockfile 和 workflow 状态。
- 固定工具链，提交测试/CI 设计。

### 第 2 天：后端单元与集成测试

- 先为状态规则、幂等、事务回滚写失败测试，再补测试支持代码。
- 让测试可在干净容器环境重复执行。

### 第 3 天：权限与前端测试

- 完成 401/403、参与者、通知和附件权限用例。
- 接入前端测试工具，覆盖关键交互。

### 第 4 天：CI 与扫描

- 接入 docs/backend/frontend/audit jobs。
- 修复环境差异、缓存和报告归档问题。

### 第 5 天：破坏性验证与文档

- 人为破坏一条状态规则，证明相应测试变红，再恢复。
- 人为制造前端编译错误，证明 CI 阻断，再恢复。
- 从空缓存、空 node_modules、空测试数据库重跑全部门禁。

- [ ] 工具版本和前端依赖可复现，CI 使用 `npm ci`。

## 9. 常见坑与求助

| 坑 | 修正方向 |
| --- | --- |
| 本地通过、CI 找不到数据库 | 测试依赖是否由 job 创建，连接配置是否测试专用 |
| 测试顺序改变就失败 | 清理共享状态、固定时间/随机数、禁止依赖上一个用例 |
| `npm ci` 报 lockfile 不一致 | 在固定 npm 版本下更新 package.json 与 lockfile |
| 权限测试全部 mock 成管理员 | 增加真实 Security 配置和非管理员身份 |
| CI 很绿但没有执行测试 | 检查日志中的测试发现数量，空套件应失败 |
| 扫描永远允许失败 | 建立分级、例外到期日和逐步收紧计划 |

求助时附：本地/CI 环境版本、完整失败 job、首个根因、测试报告、容器日志、最小复现命令和最近一次成功 commit。
