# 带教人指南

## 角色分工

| 角色 | 职责 |
| --- | --- |
| 带教人 | 定目标、下任务、Review、红线、结对难点 |
| 实习生 | 按路径学习、按任务书交付、每日同步、文档化卡点 |

## 推荐节奏

| 频率 | 活动 | 时长 |
| --- | --- | --- |
| 每天 | 站会：昨天 / 今天 / 阻塞 | 10 min |
| 每周 | Code Review + 架构问答 | 45 min |
| 节点 | W1 环境验收、W2 功能验收、W4 Demo | 各 30–60 min |
| 解锁 | W5～W12 门槛 Review（见下表） | 每周 45～90 min |

**结对时机：** 装环境、第一次 PR、第一次动权限/SQL/Security 相关、任何「结对」任务池项。

## 红线（必须讲清楚）

1. **密钥与口令不得进入 Git**（含截图发群也要注意）。
2. **默认 JWT / 数据源 / Druid 配置不得用于公网**（SEC-001/002/003）。
3. **前端隐藏 ≠ 安全**；接口必须有 `@PreAuthorize`（或等价后端校验）。
4. **代码生成器**勿在共享/生产库随意执行 DDL（SEC-007）。
5. **`master` 禁止直推**；走分支 + Review。
6. 阻塞 **> 1 小时**必须升级提问（要求：现象 / 已查路径 / 报错全文）。

## Code Review 检查清单

### 必看

- [ ] 分层是否清晰（Controller 不写复杂 SQL 业务堆砌）
- [ ] 写操作 / 敏感读是否有权限注解
- [ ] Mapper XML 是否避免用户输入直接进 `${}`
- [ ] 前端改动是否只改了展示却漏了 API 权限
- [ ] diff 中是否出现 password、secret、连接串

### 风格（与仓库一致即可）

- [ ] 命名、包结构是否贴近现有 `system` 模块
- [ ] 是否重复造轮子（已有工具类 / 统一返回）

### 可后置

- 完美单测覆盖、大范围重构、UI 视觉像素级一致

## 评价维度（优于「写了多少行」）

| 维度 | 好的表现 |
| --- | --- |
| 理解 | 能讲清登录与三层权限 |
| 工程 | PR 小、描述清、自测步骤可复现 |
| 安全意识 | 主动问权限与暴露面 |
| 沟通 | 卡点描述完整，不闷头超过半天 |
| 成长 | 第二周起减少重复问题，会查 audit/CONTEXT |

## 任务下达原则

1. 用 [03-task-template.md](./03-task-template.md)，验收可勾选。
2. **池子里的小单**（T01–T04 等）建议 ≤ 2 人日；**周任务包** W1～W12 按各自任务书节奏，不要和「≤2 人日」混为一谈。
3. **按周解锁任务书：** 只发当前周；W1→W2→W3→W4→W5→W6→W7→W8→W9→W10→W11→W12，上一周未过门槛不得提前开下一周。
4. 对零基础：开营消息里写死 `admin`/`admin123`、端口、库名；指向 `07` + `08` 再进任务书。
5. 发 W2：钉死 **仅 P0 置顶**；勿改 `isRead`。
6. 发 W3：钉死 **同模块加深**（筛选+导出+日志+文档）；导出对照 post；新权限 `system:notice:export`；默认不做 DataScope。
7. 发 W4：以 Demo/笔记/合入为主，控制新需求。
8. 安全 P1 修复默认**结对**，并对照 [04-remediation-roadmap.md](../audit/04-remediation-roadmap.md)。

### W5～W12 解锁与 Review 门槛

W5～W7 是进阶延伸，可按实习周期裁剪；一旦进入 W8，W8～W10 必须围绕同一工单领域连续演进。W11～W12 默认导师结对，不把 CI 密钥、部署凭据或真实生产权限交给实习生。

| 周次 | 解锁前提 | 导师 Review 必看 | 通过证据（满足后才发下一周） |
| --- | --- | --- | --- |
| W5 批量写 | W4 通过；先区分仓库已有用户导入与本周真实增量，裁剪好导入/部门/角色范围 | “先全量校验、再整批事务写入”；用户、部门、角色 DataScope；`userId=1` 保护；`REPLACE` 语义；两个新增权限及回滚 SQL | 混合合法/非法行时零写入；越权、管理员保护和中途异常均无半写入；三个接口有权/无权直调证据齐全 |
| W6 字典与缓存 | W5 通过；确认不重做现成字典 CRUD；先复现重命名遗留旧 key | 数据库提交后旧/新 key 失效策略；回滚时不发布未提交缓存；缓存失败恢复；用户性别筛选不改变原 DataScope | 重命名前后数据库/Redis/接口一致；重复编码和事务回滚可验证；性别筛选、未知值、403 和受限账号均通过 |
| W7 会话与统计 | W6 通过；Quartz 表和可重复 fixture 已准备；在线会话与调度统计分别评审 | 会话数、去重用户数等指标定义；`deptId` 过滤；批量权限；`exception_info` 失败归类；起止时间耗时；日期边界、空集、零除 | 双浏览器会话口径正确；固定 fixture 的总数、Top5、每日趋势与人工 SQL 一致；空数据、403、图表销毁和两个模块回归通过 |
| W8 工单 MVP | W1～W7 核心能力稳定；独立模块、ER、接口、权限、DataScope 和 SQL 方案先评审 | `ruoyi-ticket` 依赖方向；创建人/部门取登录态且不可伪造；所有权规则；DataScope 表别名；正向/回滚脚本和索引 | 干净库可迁移、可回滚；三类账号的菜单/方法/数据权限矩阵通过；跨部门不可见，客户端伪造创建人无效 |
| W9 状态与并发 | W8 已合入稳定基线，CRUD、DataScope 和回滚脚本可重复验证 | 状态规则单一来源；状态更新与流转记录事务；`requestId` 唯一约束与幂等；乐观锁条件；参与者校验 | 注入流转记录失败时整体回滚；重复请求只生效一次；两个并发请求只有一个成功；W8 回归仍通过 |
| W10 文件与通知 | W9 状态机、事务、幂等和时间线已通过 | 鉴权下载、路径与类型/大小校验；数据库与文件系统的上传/删除补偿；通知提交后触发；`eventId + receiverId` 去重；通知归属与审计快照 | 越权下载、文件丢失、数据库失败、物理删除失败、通知失败和重复事件均有证据；核心流转不被通知失败回滚 |
| W11 测试与 CI | W8～W10 业务规则和迁移脚本已稳定，人工回归可重复 | 测试分层与真实断言；测试数据/文件隔离；迁移和回滚测试；lockfile 与 `npm ci`；CI job、报告、密钥和阻断规则 | 本地与 CI 均执行非空测试套件；事务、幂等、并发、越权有自动化用例；故意破坏会变红，恢复后重新变绿 |
| W12 部署与回滚 | W11 门禁稳定通过；已确认隔离测试环境、授权边界和恢复点 | 镜像 SHA、外置配置与 secret；Swagger/Druid 等暴露面；迁移失败阻断启动；备份校验与恢复；应用/数据库/附件回滚；健康检查与发布手册 | 在空环境完成部署、升级、故障回滚和备份恢复；工单/流转/通知/附件元数据核对通过；全程不操作真实生产 |

**门槛原则：** 页面“看起来能用”不等于通过。导师至少检查一次失败路径、一次无权限路径和一次上一周回归；涉及并发、文件、CI 或部署时，必须保留可复现命令、输入、结果和清理/回滚记录。
