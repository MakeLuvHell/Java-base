# 带教人指南

## 角色分工

| 角色 | 职责 |
| --- | --- |
| 带教人 | 定目标、下任务、Review、红线、结对难点 |
| 实习生 | 按路径学习、按任务书交付、每日同步、文档化卡点 |

## 推荐节奏

| 频率 | 活动 | 时长 |
| --- | --- | --- |
| 每天 | 站会：昨天 / 今天 / 阻塞 | 10 min |
| 每周 | Code Review + 架构问答 | 45 min |
| 节点 | W1 环境验收、W2 功能验收、W4 Demo | 各 30–60 min |

**结对时机：** 装环境、第一次 PR、第一次动权限/SQL/Security 相关、任何「结对」任务池项。

## 红线（必须讲清楚）

1. **密钥与口令不得进入 Git**（含截图发群也要注意）。
2. **默认 JWT / 数据源 / Druid 配置不得用于公网**（SEC-001/002/003）。
3. **前端隐藏 ≠ 安全**；接口必须有 `@PreAuthorize`（或等价后端校验）。
4. **代码生成器**勿在共享/生产库随意执行 DDL（SEC-007）。
5. **`master` 禁止直推**；走分支 + Review。
6. 阻塞 **> 1 小时**必须升级提问（要求：现象 / 已查路径 / 报错全文）。

## Code Review 检查清单

### 必看

- [ ] 分层是否清晰（Controller 不写复杂 SQL 业务堆砌）
- [ ] 写操作 / 敏感读是否有权限注解
- [ ] Mapper XML 是否避免用户输入直接进 `${}`
- [ ] 前端改动是否只改了展示却漏了 API 权限
- [ ] diff 中是否出现 password、secret、连接串

### 风格（与仓库一致即可）

- [ ] 命名、包结构是否贴近现有 `system` 模块
- [ ] 是否重复造轮子（已有工具类 / 统一返回）

### 可后置

- 完美单测覆盖、大范围重构、UI 视觉像素级一致

## 评价维度（优于「写了多少行」）

| 维度 | 好的表现 |
| --- | --- |
| 理解 | 能讲清登录与三层权限 |
| 工程 | PR 小、描述清、自测步骤可复现 |
| 安全意识 | 主动问权限与暴露面 |
| 沟通 | 卡点描述完整，不闷头超过半天 |
| 成长 | 第二周起减少重复问题，会查 audit/CONTEXT |

## 任务下达原则

1. 用 [03-task-template.md](./03-task-template.md)，验收可勾选。
2. **池子里的小单**（T01–T04 等）建议 ≤ 2 人日；**周任务包** W1/W2 按 5 天节奏，不要和「≤2 人日」混为一谈。
3. 第 1 周**只发 W1**；W1 通过后再发 W2，避免任务过载。
4. 对零基础：开营消息里写死 `admin`/`admin123`、端口、库名；指向 `07` + `08` 再进任务书。
5. 发 W2 时钉死范围：**默认仅 P0 置顶**；字段/排序/权限用任务书推荐默认；提醒勿改 `isRead`。
6. 安全 P1 修复默认**结对**，并对照 [04-remediation-roadmap.md](../audit/04-remediation-roadmap.md)。

## 账号与数据准备（带教人）

建议预置或指导实习生自建：

| 账号用途 | 说明 |
| --- | --- |
| 超级管理员 | 走通全部菜单 |
| 业务角色 | 仅部分菜单 + 部分 `system:notice:*` 等 |
| 无权限用户 | 验证 403 与菜单不可见 |

数据：使用本地库；可定期从 SQL 重建，避免脏数据争论。

## 开营检查（带教人自己）

- [ ] 已发 [00-onboarding-message.md](./00-onboarding-message.md)（改好日期、仓库地址、站会时间）
- [ ] 只附 W1 任务书，未同时甩 W2 全文
- [ ] 已约每日站会时间（10 分钟）
- [ ] 本地能演示一版可运行系统（或远程开发机）：登录 + 用户管理
- [ ] 已确认本仓 SQL 导入后 `admin`/`admin123` 仍可用（或已在消息中写明实际密码）
- [ ] 已准备 Review 时段
- [ ] 已说明分支命名与红线（密钥、公网、生成器、>1 小时必问）
- [ ] （为 W2）准备无 `system:notice:edit` 测试账号或指导自建步骤
