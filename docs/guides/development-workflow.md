# 研发协作流程

本文定义从接收任务到合并 `master` 的统一流程，适用于功能、缺陷、安全整改、工程化和文档变更。

> **当前约定：** `master` 禁止直推，所有变更使用独立分支并经过 Review。
> **当前基线：** 截至 2026-08-03，仓库尚无业务 CI workflow；本地验证和人工 Review 是现阶段必需门禁。
> **目标状态：** W11 落地自动化测试与 PR Checks 后，将关键 job 设为合并前必过。

相关：[知识库首页](../README.md) · [数据库迁移](./database-migrations.md) · [测试策略](./testing-strategy.md) · [CI/CD](./ci-cd-pipeline.md) · [发布与回滚](./deployment-and-rollback.md)

## 1. 总体流程

```text
确认任务与基线
  → 划定范围和风险
  → 创建分支
  → 必要时先做设计评审
  → 小步实现 + 测试 + 迁移 + 文档
  → 本地验证并保存证据
  → 自查 diff
  → 提交 PR
  → Review / CI / 修正
  → 合并 master
  → 发布或交接时执行运行检查
```

任何一步发现任务依赖的能力尚不存在，先把它登记为前置条件；不能把培训目标或文档示例当成已有实现继续开发。

## 2. 接任务时先确认

### 2.1 五个基本问题

1. **为什么改：** 用户问题、业务规则或风险 ID 是什么？
2. **改什么：** 后端模块、前端页面、表、接口和配置的边界在哪里？
3. **不改什么：** 哪些相邻重构、兼容逻辑和部署工作不属于本次范围？
4. **怎么验：** 至少有哪些成功、失败、权限和回归场景？
5. **怎么退：** 代码、配置、数据库和文件副作用如何恢复？

### 2.2 现状取证

- 从当前分支读取代码、POM、`package.json`、SQL 和配置，不依赖记忆。
- 在 [docs/README.md](../README.md) 确认能力是“当前”还是“目标”。
- 涉及安全边界时查 [安全审计](../audit/03-security.md) 与[整改路线](../audit/04-remediation-roadmap.md)。
- 记录无法执行的验证及原因，例如本机没有 JDK/Maven。

## 3. 分支与工作区

### 3.1 分支命名

| 类型 | 格式 | 示例 |
| --- | --- | --- |
| 功能 | `feature/<name>-<topic>` | `feature/lin-ticket-search` |
| 缺陷 | `fix/<issue>-<topic>` | `fix/142-notice-export` |
| 安全 | `security/<risk-id>-<topic>` | `security/sec-003-ops-endpoints` |
| 文档 | `docs/<topic>` | `docs/knowledge-base` |

分支从最新本地 `master` 创建。并行任务优先使用隔离工作树，避免把其他未完成改动带入当前 PR。

### 3.2 主分支红线

- 不直接在 `master` 开发或推送。
- 不使用强制推送覆盖共享分支。
- 不把多个无关需求塞进同一个 PR。
- 不在合并时跳过已约定的 Review、测试或迁移检查。

紧急修复也走短分支和最小 Review；事后补齐验证与事件记录，不能把“紧急”变成长期绕过流程的理由。

## 4. 何时必须先评审设计

出现任一情况，编码前提交简短设计：

- 新增 Maven 模块、跨模块依赖或公共接口。
- 新表、改字段、数据回填、菜单 / 字典 SQL。
- 认证授权、DataScope、附件、任务执行或外部输入处理。
- 状态机、事务、并发、幂等或异步副作用。
- 新依赖、测试框架、CI workflow、容器或部署拓扑。
- 破坏兼容性的 API、配置或数据变化。

设计至少写清：范围 / 不做、数据与接口契约、权限矩阵、失败路径、测试方案、迁移 / 回滚、发布影响。W8-W12 使用各周任务书中的强制设计评审清单。

## 5. 实现约定

### 5.1 控制变更范围

- 沿用现有模块职责、返回结构、权限注解和前端组件模式。
- 业务规则放在可测试的 Service / 领域边界，不堆进 Controller 或 Vue 模板。
- 权限以后端为准；前端按钮隐藏只改善体验，不能替代接口校验。
- 不顺手升级大版本、格式化全仓或重构无关代码。
- 配置示例使用占位符；真实口令、Token、连接串和生产地址不得进入 Git。

### 5.2 配套交付

| 改动 | 同一 PR 必须考虑 |
| --- | --- |
| 数据结构 / 基础数据 | 版本迁移、回滚或前滚策略、空库和旧版本升级验证 |
| API / DTO | 权限、错误契约、接口文档、前端调用兼容性 |
| 业务规则 | 单元 / 集成测试、并发与事务失败场景 |
| 前端交互 | 加载 / 空 / 错误 / 无权限 / 冲突状态、关键测试 |
| 配置 / 依赖 | 环境差异、secret 来源、构建和发布说明 |
| 日志 / 指标 | 敏感字段、request ID、告警或 runbook 影响 |

数据库规范见[数据库迁移](./database-migrations.md)，验证范围见[测试策略](./testing-strategy.md)。

## 6. 提交与 PR

### 6.1 提交要求

- 一个提交表达一个可解释的变化，提交信息说明目的而非文件名列表。
- 提交前查看 `git diff` 和 `git status`，排除构建产物、IDE 文件、日志和密钥。
- 不改写他人的未完成提交；需要拆分或重排共享历史时先协调。

推荐提交信息：

```text
feat: add ticket assignment validation
fix: enforce notice export permission
test: cover ticket transition conflicts
docs: add database migration guide
```

### 6.2 PR 描述最小内容

```markdown
## 背景与范围
- 解决的问题 / 风险 ID
- 本次做什么、不做什么

## 关键设计
- 数据、接口、权限、事务或兼容性决定

## 验证
- 命令、环境、测试数量和结果
- 手工场景与截图 / 请求证据

## 迁移与回滚
- 迁移顺序、兼容窗口、恢复步骤

## 风险与未验证项
- 已知限制、后续工作、无法执行的检查及原因
```

“已自测”“CI 通过”不能代替命令、测试数量和结果摘要。

## 7. Review 顺序

Reviewer 按以下顺序检查：

1. **需求符合性：** 是否解决原问题，有无漏项或越界。
2. **安全与数据：** 权限、DataScope、输入输出、敏感信息、迁移和回滚。
3. **正确性：** 事务、并发、幂等、失败路径和兼容性。
4. **验证质量：** 测试是否会在缺陷复现时失败，空套件是否可能假绿。
5. **可维护性：** 模块边界、命名、重复、文档和运维影响。

重要问题修正后必须重新 Review 受影响范围。不要仅凭评论回复“已处理”关闭问题。

## 8. 完成定义

### 8.1 合并前

- [ ] 范围与验收条件全部对应到实现或明确的未做项。
- [ ] 权限、错误、空数据、边界和回归场景已验证。
- [ ] 相关测试已运行，命令和结果已记录；无测试时说明原因与风险。
- [ ] 数据变化有迁移、版本顺序和恢复方案。
- [ ] 配置、文档、API 说明和运维步骤已同步。
- [ ] diff 无真实密钥、生成产物、调试代码和无关格式化。
- [ ] PR Review 已完成；已落地的关键 CI job 全部通过。

### 8.2 发布前

- [ ] 制品可追溯到明确 commit / tag，不只依赖 `latest`。
- [ ] 环境配置和 secret 来源已确认，不使用仓库示例值。
- [ ] 数据库备份 / 恢复点、迁移门禁和兼容窗口已确认。
- [ ] 健康检查、冒烟场景、观察窗口和回滚判定已写清。
- [ ] 操作者、时间、版本、结果和遗留项可追溯。

发布步骤见[发布与回滚](./deployment-and-rollback.md)，观测和事件处理见[可观测性与运维](./observability-and-operations.md)。

## 9. 验证证据怎么留

| 证据 | 最低要求 |
| --- | --- |
| 自动测试 | 完整命令、退出码、测试数量、失败数 |
| 构建 | 工具版本、命令、制品名称 / 大小或成功摘要 |
| 手工验证 | 角色、前置数据、步骤、预期、实际结果 |
| 数据迁移 | 起始版本、脚本版本、校验值、行数 / 结构检查 |
| 安全检查 | 身份、入口、预期状态码、日志脱敏抽样 |
| 发布演练 | 环境名、commit / 镜像 SHA、时间线、健康 / 回滚结果 |

证据可写入 PR、测试报告或任务要求的技术笔记，但不得包含 secret 和真实个人数据。

## 10. 文档变更流程

纯文档 PR 仍需：

- 核对当前路径、版本、命令和配置键。
- 检查所有相对链接和新增文件末尾换行。
- 区分当前基线、目标状态和历史快照。
- 更新 [docs/README.md](../README.md) 或本目录索引中的导航。
- 说明没有运行哪些业务构建，以及为什么不需要或无法运行。
