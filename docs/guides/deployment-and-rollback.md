# 发布、升级与回滚指南

本文定义如何把经过验证的提交交付到隔离测试环境，并为未来生产发布建立可审计的操作基线。

> **当前基线（2026-08-03）：** 仓库有基础 Maven 打包、jar 启停和前端安装批处理脚本，但没有 Dockerfile、Compose、部署 workflow、版本化发布编排或完整回滚 runbook。本文不是当前可直接执行的生产手册。
> **目标状态：** W12 在本地 / 隔离测试环境落地可追溯制品、外置配置、迁移门禁、健康检查、升级、回滚和恢复演练。
> **授权边界：** 培训任务不得操作真实生产环境或真实生产数据。

相关：[数据库迁移](./database-migrations.md) · [CI/CD](./ci-cd-pipeline.md) · [可观测性与运维](./observability-and-operations.md) · [W12 任务书](../intern/tasks/W12-deployment-production-readiness.md)

## 1. 发布成功的定义

“容器已启动”或“进程存在”不代表发布成功。一次发布至少满足：

1. 制品可追溯到唯一 commit / tag，构建记录可查询。
2. 配置和 secret 来自目标环境，不固化在源码或镜像中。
3. 数据库迁移成功且版本、校验值、备份点已记录。
4. liveness 与 readiness 均通过，依赖状态符合设计。
5. 登录、权限和本次改动的关键冒烟通过。
6. 观察窗口内错误率、延迟和资源没有不可接受退化。
7. 回滚判定、负责人和恢复步骤在发布前已经确认。

### 1.1 现有辅助脚本边界

| 脚本 | 当前行为 | 不能证明的能力 |
| --- | --- | --- |
| `bin/package.bat` | 执行 Maven 打包，且显式跳过测试 | 质量门禁、可追溯制品、发布批准 |
| `bin/run.bat` | 从后端 target 目录启动 jar | 迁移、健康检查、守护、回滚 |
| `ry.sh` / `ry.bat` | 对固定 jar 名执行启动、停止、重启、状态 | 多环境配置、版本切换、就绪检查 |
| `ruoyi-ui/bin/package.bat` | 使用 `npm install` 安装前端依赖 | lockfile 复现、测试、生产构建与发布 |

这些脚本可作本地辅助入口，但不能直接作为 W12 发布 runbook。正式流程需要补齐测试门禁、明确制品版本、配置 / secret、迁移、健康、观察和恢复步骤。

## 2. 目标拓扑与边界

W12 默认单体拓扑：

```text
Browser
   |
Nginx / web
   |-- static ruoyi-ui
   `-- /prod-api --> ruoyi-admin
                         |-- MySQL
                         `-- Redis

one-shot migration job --> MySQL
persistent upload volume --> ruoyi-admin
```

- 只有 Web 入口面向业务网络；MySQL、Redis、迁移端点和指标端点位于受控网络。
- migration job 成功后 backend 才能进入新版本启动阶段。
- 上传目录独立持久化，不能随应用容器替换而丢失。
- 生产应关闭或限制 Swagger、Druid 和 generator，具体风险见[安全审计](../audit/03-security.md)。

拓扑正式落地后，以仓库中的 Compose / 部署清单和环境 runbook 为准，并回写本文的当前基线。

## 3. 制品规范

### 3.1 后端

- 在固定 JDK 17 / Maven 环境构建，保留依赖和测试记录。
- 运行制品只包含所需 jar / 配置入口，不包含源码、Maven 缓存或构建 secret。
- 运行镜像使用明确版本的 JRE 17 基础镜像和非 root 用户。
- 标签至少包含发布版本或 commit SHA；摘要 digest 进入发布记录。

### 3.2 前端

- 在团队确认的固定 Node/npm 版本和 lockfile 下使用 `npm ci`。
- 运行镜像仅包含 Nginx、静态产物和明确的代理配置。
- API 基础路径由构建 / 运行约定管理，不写死测试机或生产 IP。
- Nginx 配置上传大小、缓存策略、超时和必要安全响应头。

### 3.3 制品清单

每次候选发布记录：

| 项 | 示例格式 |
| --- | --- |
| 源码 | commit SHA、tag、分支 |
| 后端 | jar 名称 / 哈希，或镜像 registry:tag@digest |
| 前端 | dist 包哈希，或 web 镜像 digest |
| 数据库 | 起始版本、待执行 V 版本及校验值 |
| 配置 | 配置版本 / 来源，不记录 secret 值 |
| 验证 | CI run、测试报告、扫描报告 |

禁止只保留可变的 `latest` 标签作为唯一回滚依据。

## 4. 配置与 secret

至少区分 dev / test / prod，明确每项来源与负责人。

| 配置类别 | 要求 |
| --- | --- |
| MySQL / Redis | 运行时注入；账号最小权限；不使用仓库示例口令 |
| JWT secret | 密钥系统或受控 secret 文件注入；轮换会使现有登录态失效 |
| `ruoyi.profile` | 指向持久化上传卷；目录权限最小化 |
| Swagger / Druid | 生产关闭，或仅管理网络与授权身份可达 |
| CORS | 显式可信 Origin，不使用宽泛生产默认值 |
| 日志 | 生产 info / warn 为主，脱敏且有轮转 |
| generator | 生产移除、禁用或确保入口不可达 |

缺少必需 secret、仍使用已知默认值、目录不可写或环境标识不明确时，部署门禁必须失败。不要为了让健康检查变绿而降低认证或暴露控制。

## 5. 发布前检查

### 5.1 变更与授权

- [ ] 目标环境、发布窗口、操作者和 Reviewer 已确认。
- [ ] commit / tag / 镜像 digest 与已通过验证的版本一致。
- [ ] PR、必要 CI、依赖 / 镜像扫描结果可追溯。
- [ ] 变更清单包含代码、配置、迁移、菜单 / 字典和上传影响。
- [ ] 未解决风险、临时例外、负责人和到期日已记录。

### 5.2 环境与容量

- [ ] 主机、网络、域名、端口、时区和 DNS 符合清单。
- [ ] MySQL / Redis 版本与目标配置兼容，容量和连接数有余量。
- [ ] 磁盘可容纳镜像、日志、数据库临时空间和上传增长。
- [ ] 当前服务、数据库版本、配置版本和关键指标基线已记录。

### 5.3 恢复点

- [ ] 数据库备份已完成并计算校验值。
- [ ] 备份在独立实例做过恢复验证，而非只确认文件存在。
- [ ] 上一版应用和前端制品仍可获取。
- [ ] 上传卷有一致性策略和独立备份 / 清单。
- [ ] 回滚负责人、判定阈值和最长决策时间已确认。

## 6. 标准发布时序

```text
冻结候选版本
  → 检查授权、配置和恢复点
  → 拉取按 digest 固定的制品
  → MySQL ready
  → 执行 migration job
  → 校验迁移版本 / 校验值 / 业务行数
  → 启动 backend
  → backend liveness + readiness
  → 启动或切换 web
  → 技术冒烟 + 业务冒烟 + 权限冒烟
  → 观察窗口
  → 宣布成功或执行回滚
```

每一步都必须有超时、失败处理和负责人。自动化脚本失败时停止，不允许手工跳过红色步骤后继续发布。

## 7. 数据库迁移门禁

发布前读取[数据库迁移规范](./database-migrations.md)，并记录：

- 当前版本和待执行版本。
- 每个 V 文件的校验值与评审记录。
- 预计锁表 / 回填时间和应用兼容窗口。
- 备份点、U 脚本适用条件和前滚修复方案。

迁移 job 任一情况失败都不得启动新 backend：连接目标不明确、版本断档、校验值被改、锁获取失败、SQL 失败、验证行数不符。

数据库向后兼容时，可先完成 expand 迁移再滚动应用；不兼容时必须安排停写并明确旧版本何时不可再运行。

## 8. 健康检查与冒烟

### 8.1 健康层次

| 层次 | 验证 |
| --- | --- |
| 容器 / 进程 | 进程存在，无持续重启 |
| Liveness | 应用主循环存活；短时依赖故障不应无限重启应用 |
| Readiness | 应用能安全接收请求；关键数据库 / Redis / 迁移状态符合设计 |
| Web | 静态页面加载，API 代理、超时和状态码正确 |
| 业务 | 登录、菜单、权限、本次改动和关键写读闭环 |

### 8.2 最小冒烟矩阵

- 正常用户登录、加载动态路由并读取一个列表。
- 无权限用户访问敏感接口返回 403，而不是只隐藏按钮。
- 本次发布的核心写操作完成后可查询，审计信息正确。
- 未登录访问 Swagger / Druid / 受保护附件被拒绝或不可达。
- 数据库 / Redis 未就绪时 readiness 失败且日志可定位。
- request ID 能从入口串联到后端日志。

只使用专门测试账号和脱敏数据；冒烟产生的数据需要标记并在批准的范围内清理。

## 9. 观察窗口

发布后在预先约定的窗口观察：

- HTTP 5xx、4xx 异常变化、P95 延迟和请求量。
- JVM 内存 / GC / 线程、数据库连接池、Redis 错误。
- 应用启动异常、迁移错误、重复重启和日志速率。
- 业务关键指标及本次功能的失败事件。
- 磁盘、日志和上传卷增长。

指标定义、告警和事件分级见[可观测性与运维](./observability-and-operations.md)。没有观测信号时不能仅凭“暂时没人反馈”判断发布正常。

## 10. 回滚判定

发布前为本次变化写明阈值。以下情况通常立即停止继续发布并评估回滚：

- 健康 / 就绪持续失败或实例反复重启。
- 核心登录、权限、写入或数据读取不可用。
- 出现数据损坏、越权、敏感信息泄露或不可控重复副作用。
- 错误率、延迟、资源或业务失败明显越过已批准阈值。
- 迁移结果与预期结构、行数或校验值不一致。

安全事件先隔离暴露面和保全证据；不要为了恢复可用性删除审计记录。

## 11. 回滚路径

### 11.1 仅应用回滚

适用：迁移向后兼容，旧应用能安全使用当前 schema。

```text
停止扩大流量
  → 切回上一明确 digest
  → 等待 readiness
  → 执行旧版本冒烟
  → 观察错误与数据一致性
```

保留新迁移，后续通过新 V 前滚修复。禁止擅自把版本台账标记为未执行。

### 11.2 应用与数据库回滚

适用：新结构 / 数据与旧应用不兼容，且已批准 U 或恢复方案。

1. 停止写流量和后台任务。
2. 记录故障时点、迁移版本和新数据范围。
3. 备份当前故障状态用于分析。
4. 执行已在相同基线验证的 U，或恢复备份到新数据库实例。
5. 核对 schema、关键行数、状态和权限数据。
6. 启动上一版应用并完成冒烟。

涉及数据丢失时必须由业务 / 数据负责人明确批准。共享环境中优先恢复到新实例，保留故障库只读证据。

### 11.3 附件与外部副作用

数据库回滚不会自动恢复文件、已发送通知或外部调用：

- 上传卷按清单核对新增、删除和孤儿文件。
- 先隔离待清理文件，保留恢复窗口，不立即物理删除。
- 已发送通知通过补偿或更正事件处理，不能假装未发送。
- 定时任务和消费者先暂停，避免回滚过程中继续写入。

## 12. 备份与恢复演练

至少在隔离环境完成：

1. 记录应用、迁移和配置版本。
2. 备份数据库与附件清单，保存校验值。
3. 修改一组可识别的测试数据。
4. 将备份恢复到另一实例。
5. 核对表结构、关键行数、权限、业务状态和附件元数据。
6. 使用目标应用做只读与有限写入验证。

备份文件不得进入 Git；含真实个人数据的备份不得用于培训或普通测试环境。

## 13. 环境误操作防护

- 环境、Compose project、数据库和卷使用明确且不同的名称。
- 破坏性命令禁止依赖未解析变量、当前目录猜测或宽泛通配符。
- 脚本启动时显示目标并要求针对高风险操作二次确认。
- 生产凭据只对授权 job / 人员可用，测试流水线无法读取。
- 部署账号与迁移账号分离，应用运行账号不持有 DDL 权限。
- 发布 / 回滚日志记录操作者和目标，但屏蔽 secret 值。

## 15. 落地完成定义

- [ ] 干净测试机可按仓库文档启动完整系统。
- [ ] 制品固定版本并可追溯，不依赖唯一 `latest`。
- [ ] 配置 / secret 与镜像分离，默认敏感配置不会进入生产。
- [ ] migration 失败阻断 backend，新旧版本兼容性已验证。
- [ ] 健康检查区分 liveness 和 readiness。
- [ ] 登录、权限、核心业务和受保护端点冒烟可重复。
- [ ] 观察信号、回滚阈值、负责人和操作窗口明确。
- [ ] 应用回滚、数据库恢复、附件核对均已在隔离环境演练。
- [ ] 非作者能按 runbook 复现，命令不会误指向其他环境。
